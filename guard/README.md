# guard 健康守护

「不影响正常使用」的最后一道保险。引擎负责拦截，guard 负责盯着有没有拦错，拦错了就自动收手，并告诉你。

## 详细功能

### 1. 收集误伤信号
各引擎把可疑情况写进数据层的 `signals` 表，guard 统一处理：

| 信号 | 来源 | 含义 |
|---|---|---|
| 用户撤销 | 无障碍引擎、界面 | 你点了「撤销」，说明这次拦截不该发生 |
| 临时放行 | 界面 | 你觉得某个 App 坏了，点了一键放行 |
| 重试风暴 | VPN 引擎 | 被拦截的域名在 60 秒内被同一 App 反复请求 ≥10 次，说明 App 离不开它 |
| 崩溃弹窗 | 无障碍引擎 | 系统弹出「XX 已停止运行」 |
| 反复冷启动 | 无障碍引擎 | 同一 App 60 秒内被启动 ≥3 次 |
| 崩溃记录 | 系统净化引擎（Shizuku） | 系统崩溃日志里出现该 App |

### 2. 定位并自动降级
- 根据信号类型，找出这个 App 最近（2 分钟或 10 分钟内）命中过的规则；
- **只对这个 App 停用这些规则**，其他 App 不受影响；
- 用户之前「钉住」过的规则不会被停用；
- 找不到相关规则时，提醒你可以临时放行。

### 3. 提醒与撤销
- 每次自动降级都发一条通知，同时出现在首页：「XX 疑似受影响，已自动降级 [查看] [撤销]」；
- 点「撤销」= 恢复这些规则，并把它们钉住，以后 guard 不再停用。

### 4. 观察期评估
- 新装 App 的 3 天观察期到期后，由 guard 评估：
  - 观察期内有过撤销或临时放行 → 延长 3 天并提醒；
  - 没有 → 结束观察，开始正常拦截。
- 每小时检查一次是否有到期的 App。

## 结构
- `com.sentinel.guard.policy`：纯 Kotlin 决策逻辑（信号 → 决定），可在电脑上直接测试。
- `com.sentinel.guard.runtime`：在主进程订阅信号、执行决定、发通知、处理撤销按钮、定时评估观察期。
