# engine-vpn 网络拦截引擎

在独立的 `:vpn` 进程里运行一个本地 VPN。它**只接管 DNS 查询和已知的 HttpDNS 地址**，其他网络流量不经过它，所以不影响网速。

## 详细功能

### 1. DNS 过滤
- 系统 DNS 指向一个虚拟地址（`10.111.0.2`），所有 App 的域名查询都会先到这里。
- 查到的域名按规则判断：
  - 命中广告规则 → 返回「空地址」，广告加载不出来；
  - 没命中 → 通过加密 DNS（DoH）向上游查询真实地址，带缓存。
- 判断时考虑：这个 App 的拦截级别（标准 / 强力）、是否处在观察期、guard 是否对它停用了这条规则、是否处在激励视频的奖励窗口。
- 观察期内的 App：只记录「本来会拦截的域名」，不真正拦截。

### 2. HttpDNS 快速拒绝
- 已知 HttpDNS 服务的 IP 段也路由进 VPN。
- 收到连接请求立刻回「拒绝」（TCP 回 RST，UDP 回 ICMP 不可达），App 马上改用系统 DNS，再被我们过滤；不会出现干等超时、打开变慢的情况。

### 3. 分应用
- 银行/支付类、你设为「关」的 App、临时放行中的 App：完全不经过 VPN。
- 这份名单变化时，无缝重建 VPN 接口（先建新的再关旧的，不断网）。

### 4. 激励视频的奖励窗口
- 广告 SDK 的投放域名默认拦截；无障碍引擎发现你点了「看视频领奖励」时，会打开 60 秒窗口，窗口内放行这些域名，奖励照常发放。

### 5. 误伤探测
- 同一 App 在 60 秒内反复请求同一个被拦截的域名 ≥10 次（重试风暴），上报给 guard。

### 6. 守护与容错
- 前台服务常驻，通知栏显示「今日拦截 N」和「暂停 5 分钟」按钮。
- 每 5 分钟检查无障碍、通知监听是否还开着，掉了就提醒你重新开启。
- 检测到系统「私人 DNS」处于指定服务器模式（会让拦截失效）时提醒你关闭。
- 开机自动启动；新装/卸载 App 时更新登记。
- **任何内部错误都会先关闭 VPN 接口再退出**，网络自动恢复直连，绝不会出现断网。
