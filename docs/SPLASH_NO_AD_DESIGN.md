# 开屏广告「不出现」方案设计（以百度网盘为样本）

日期：2026-10-02　状态：设计稿，待用户拍板后实施
前提：不 root；目标机华为 OCE-AN50（HarmonyOS 4.2），原定 OPPO Find X7 Ultra；Shizuku 可用（项目已有 ShizukuGateway）。

## 1. 先说清楚：能做到什么，做不到什么
- **「看到广告再点跳过」永远有延迟**（广告画出来 → 事件 → 扫描 → 点击，实测 0.5～1 秒），做不到 0 秒。
- **启动遮罩**只是把广告盖住，用户看到的是一屏空白，体验没有改善，已撤销。
- 真正让用户「完全看不到」，只能在广告**被请求/被渲染之前**拦掉。能不能做到，取决于广告是怎么来的。下面是源码层面查到的事实。

## 2. 源码层面的事实（反编译 base.apk 得出）
| 事实 | 证据 | 含义 |
|---|---|---|
| 冷启动开屏广告就画在 `MainActivity` 自己的窗口里 | 广告出现时无障碍树里同时有首页节点和「跳过 05」，且活动名是 `MainActivity` | 禁用 `SplashAdActivity` 这类组件大概率无效 |
| 多家联盟竞价：穿山甲、广点通、百度联盟、Ubix、Vlion、Octopus、美数 + 自营（biz/xz/mars） | `AdvertiseConfig` 的各 `xxxColdSwitch`、`bd_ad_bidding_config.json` | 只拦一两家，另一家补位 |
| 开关/频次/冷启动间隔由服务器下发，SVIP 有免广告逻辑 | `AdvertiseConfig`、`FreeAdvertiseProxy`、`/rest/2.0/membership/advertise/period` | 我们改不了 |
| 素材每次冷启动重新下载 | 外部缓存目录里的哈希文件时间与启动时间对应 | 断网络有机会让广告出不来 |
| 已被拦的 11 个域名全是广点通/穿山甲，但开屏仍出现 | VPN 事件表 | 真正出广告的是另外的通道 |
| 自带 HTTPDNS：`https://httpsdns.baidu.com/v6/0010/`，且硬编码 IP `180.76.76.76` | dex 字符串 | 它的域名解析可能绕开系统 DNS |
| `httpsdns.baidu.com` 已在 `HttpDnsCatalog.domains`，但 `180.76.76.76` 不在 `cidrs` | `core-rules/.../HttpDnsCatalog.kt` | 按域名能挡，按 IP 直连挡不住 |
| VPN 是「只接管 DNS」的设计，不转发应用流量 | `PacketLoop` | 做不了按 SNI/按 IP 的应用级拦截，也做不了「断网几秒」 |

## 3. 方案分层
### A. 断广告数据（预防，第一优先）
- A1　**按 App 的广告域名包**：用「静态扫描 APK」提取广告 SDK 域名（本次 12 个已列出），按 App 生成域名包。已验证可行，可复用到其他 App。
- A2　**让百度 HTTPDNS 失效，逼它回落到系统 DNS**：把 `180.76.76.76` 等 HTTPDNS 服务 IP 补进 `HttpDnsCatalog.cidrs`（向后兼容新增，需走 `docs/CHANGE_REQUESTS.md`，`ALLOW_FROZEN=1`）。回落后 `mobads.baidu.com` 等百度联盟域名才能被现有 DNS 规则拦住。
- A3　**风险**：若网盘开屏的主要来源是自营通道且走 `pan.baidu.com`，就没法按域名拦，A 对它无效。

### B. 断渲染路径（需要实验）
- B1　Shizuku 禁用开屏相关组件：因为广告画在 `MainActivity` 里，预计无效；做一次 5 分钟的实验确认即可。
- B2　清广告缓存：外部缓存目录能清，但开屏素材在应用私有目录，Shizuku 也够不到。

### C. 兜底：更快跳过（已做）
- 开屏规则窗口 5 秒 → 12 秒；扫描由去抖改限频（100ms）；点桌面图标即标记「桌面启动」。
- 仍有 0.5～1 秒的闪现，这是上限。

### D. 唯一能「硬保证」的做法（不建议先做）
- 改包（重打包/注入）或 LSPosed/LSPatch 钩住开屏流程。代价：签名变了会导致登录/风控异常、每次更新要重做、维护成本高。只有在 A/B 做完仍不满意时再讨论。

## 4. 实施顺序与验收
1. **实验（半天内）**
   - E1　飞行模式冷启动网盘：开屏是否还出现？若仍出现 → 素材有本地缓存，网络层预防的上限很低。
   - E2　先关再开保护（清掉 DNS 缓存），立即从桌面冷启动一次，读 VPN 的域名日志：网盘到底查询了哪些域名。
   - E3　Shizuku/ADB 禁用 `SplashAdActivity`，看是否消失（预计无效）。
2. **做 A1 + A2**，把 E2 里确认是纯广告的域名加入拦截；`httpsdns` 的 IP 补进目录。
3. **验收口径改成统计，不看单次**：同一台机器、保护开启、从桌面冷启动 20 次（间隔 ≥ 70 秒，避免触发守卫），记录「出现广告的次数」和「广告可见时长」。改造前后各测一轮，对比。
4. 守卫的「应用反复重启」会停规则，测试要避开；这条策略另行评估。

## 5. 需要你决定
- 是否接受「大幅降低出现率，但不保证 100%」？要 100% 只剩方案 D。
- 是否同意把 `180.76.76.76` 加入 `HttpDnsCatalog.cidrs`（会让依赖该 IP 的百度 HTTPDNS 请求失败，回落系统 DNS）。
