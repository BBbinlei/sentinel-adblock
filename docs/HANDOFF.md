# Claude / Codex 接力规则

> 本项目由两个 AI 协作：**Claude 负责 `app` 模块**，**Codex 负责其余所有模块**。任何一方额度耗尽，另一方接手它没做完的任务。工作状态只存在仓库里，不存在任何一方的会话里。

## 1. 开始工作前（接手方、新会话都一样）

1. 读 `MASTER_PLAN.md`（Global Constraints、设计补充）、`docs/CONTRACTS.md`、`docs/PROGRESS.md`。
2. 读你负责（或接手）模块的 `README.md` 与 `PLAN.md`。
3. **先跑一遍该模块的测试**，以实际结果为准，不要相信 `PROGRESS.md` 的自述。
4. 从 `PROGRESS.md` 中该通道的「下一步」继续。

## 2. 工作中必须维护的状态

- `docs/PROGRESS.md` 里每个通道有一行标题：`## [通道名] 状态: <值> | 负责方: <codex|claude|用户> | ...`。
  - 状态取值：`待办`、`进行中`、`等待`（等其他通道合并后才能继续，见该通道的 `wait_for`）、`完成`（本通道关卡已通过，等待合并）、`已合并`。
  - **监督脚本只认这一行的「状态」**，请严格按格式写。
- **一个 Task 一次提交**，提交说明含 Task 编号。
- 每完成或开始一个 Task，更新该通道的 Task 表和「下一步」，并随同提交。
- 要中断时：先 `git commit -m "wip(<模块>): Task N <做到哪>"`，再在「下一步」写清楚剩下什么。不要把半成品留在工作区。
- 关卡通过后：写 `testing/reports/<关卡>-<日期>.md`，把状态改成 `完成`。

## 3. 写入边界

| 角色 | 可写 | 只读 |
|---|---|---|
| Codex 通道 | 自己模块目录 | 其他一切（`:app`、`data`、`core-rules` 在 `g2-frozen` 之后冻结） |
| Claude | `app/`；合并通道里的 `main` | 其他一切 |

**接手期间**：接手方临时获得被接手模块的写权限。冻结项、契约（`docs/CONTRACTS.md`）、依赖方向、「不 push」的规则**不放松**。

## 4. 接力触发与返还

| 情形 | 接手方 |
|---|---|
| Codex 额度耗尽 | Claude 接着做 Codex 的通道 |
| Claude 额度耗尽 | Codex 接着做 app 通道和合并通道 |
| 额度恢复 | 原负责方**不自动抢回**；接手方做完当前 Task 并更新 `PROGRESS.md` 后，由用户决定是否交还 |
| 双方都耗尽 | 停在最近一次提交；额度刷新后由 `scripts/supervisor` 自动唤醒继续 |

接手规则：
- 不重写前人已通过测试的代码，只补未完成的 Task。
- 发现前人产出不符合 PLAN：先登记到 `PROGRESS.md` 的「已知问题」，再修。
- 合并前统一用 `scripts/check-merge.sh <模块>` 检查，谁接手都用同一套标准。

## 5. 硬性禁止

- `git push`、改远端、改 `main` 的历史、`git reset --hard` 他人提交。
- 新增或升级依赖版本（`gradle/libs.versions.toml` 冻结）。
- 引擎引用 guard 或其他引擎；在引擎代码里写奖励窗口/信号的字面量。
- 注释或跳过失败测试来「通过」关卡。
- 需要真机的步骤（M0 实机核实、`DI-*`、`AC-*`）：不要自行执行，在 `PROGRESS.md` 标「等用户」。
