# 真机检查单（Find X7 Ultra）

> 用例定义来源：`testing/device-integration/PLAN.md` Task 3。本文件是其可勾选版本；判定标准若与 PLAN 不一致，以 PLAN 为准并同步修改本文件。
> 每次执行复制 `reports/TEMPLATE.md` 为 `reports/<关卡>-<YYYY-MM-DD>.md` 记录结果；本文件中的「记录」栏可作为草稿，正式结论写入报告。

## 执行前准备

- [ ] 已获得手机主人同意，本次执行的关卡与用例范围已确认。
- [ ] 手机已开启「开发者选项 → USB 调试」，用数据线连接 Mac，`adb devices` 能看到设备（多台设备时设置 `ANDROID_SERIAL`）。
- [ ] 记录设备信息：`adb shell getprop ro.build.display.id`、`adb shell getprop ro.build.version.release`、`adb shell getprop ro.build.version.oplusrom`。
- [ ] 记录 App 版本与提交：`adb shell dumpsys package com.sentinel.adblock | grep versionName`，以及 `git rev-parse --short HEAD`。
- [ ] 电量 ≥50%，连接稳定 Wi-Fi；关闭其他 VPN / 代理 / 广告拦截类 App（DI-14 除外）。
- [ ] 准备录屏或截图工具（`adb shell screenrecord`、`adb exec-out screencap -p`），证据统一存放在 `testing/device-integration/reports/evidence/<关卡>-<日期>/`（若证据含个人信息，不入库，只在报告中写存放位置）。
- [ ] 准备事件表查看方式（App 内「日志」页，或 debug 构建的调试状态接口）。

## 安全提示

1. **任何修改系统设置的步骤都必须写明撤销步骤**，执行完用例立即撤销，并在「记录」栏注明「已撤销」。
2. 修改前先记录原值（如 `adb shell settings get <namespace> <key>`），撤销时恢复到原值而不是默认值。
3. 不在手机上执行 root、刷机、清除数据（`pm clear`）等不可逆操作；需要清数据的用例（DI-52 全新安装）只针对 `com.sentinel.adblock`。
4. 不得截取/提交含个人隐私的截图（聊天、通讯录、支付页面）；必要时打码。
5. 故障演练（DI-61*）只针对本 App 的进程与文件；损坏规则文件前先备份。
6. 任一步骤出现断网、App 无法使用等「故障让手机不可用」的情况：立即停止防护（或卸载本 App）恢复网络，记录为未通过（违反 Global Constraints「任何故障只能让拦截变弱」）。
